# AI 使用与贡献说明

本项目由 Codex 在用户授权的工作目录中实际完成需求拆解、架构选择、代码与合成数据生成、依赖安装、命令执行、pytest 编写与调试、模型接口接入、Trace 检查、文档编写和 GitHub 交付操作。没有使用多 Agent 协作。

实际执行的 AI 辅助工作包括：

- 根据原始任务制定状态模型、工具协议、事务边界与 Guard。
- 实现 Python CLI、OpenAI-compatible 原生 Tool Calling 循环及离线模拟器。
- 生成确定性工程测试，运行测试并检查真实 SQLite 结果与 Trace。
- 使用用户指定的 DeepSeek `deepseek-flash` 作为项目运行时模型。其真实工具选择和 usage 留存在 live 证据中。
- 通过浏览工具核对公司公开背景和提供方官方 Tool Calling 文档；这些页面不提供公司内部规则。
- 自动生成评估矩阵、文档和最终交付索引，数值来自实际文件。

本次观察到的人工贡献：用户提供完整项目要求、指定模型服务与目标 GitHub 账号，并授权创建仓库。API Key 仅存本地忽略配置，交付材料中不包含密钥。

没有证据表明用户已逐行审核代码、亲自调试或独立修改本次生成的实现，因此本文件不把这些工作归于用户。若用于个人笔试提交，请由提交者实际阅读、运行和解释后填写以下条目：

| 待提交者填写 | 实际记录 |
|---|---|
| 自主设计或修改的部分 | 尚未提供 |
| 独立发现并修复的问题 | 尚未提供 |
| 亲自运行的命令及结果 | 尚未提供 |
| 已理解并能解释的关键实现 | 尚未提供 |

pytest、离线模拟和真实 DeepSeek 运行是三类不同证据。Codex 自身生成代码的过程、MockModel 的固定分支、受控测试模型均不作为项目 LLM 自主决策的证据。

后续由用户要求对项目进行审核并修复。Codex 实际完成了新增回归测试、修复前失败验证、SQLite 同 ID 重排与历史记录、严格元数据类型、结构化确认输出、显式排期同步、候选边界提示及真实模型复验。首轮真实复验出现模型漏查边界的失败，保留原记录后改进工具返回信息并重新验证；详细过程见 [审核修复说明](07-review-fixes.md)。未据此增加未经证实的人工贡献。

本轮用户要求模拟实际业务并上传当前更新。Codex 核验工作区已有的状态一致性、批次避让及路径修复，独立重跑完整测试，新增模拟运营脚本并实际调用配置的 DeepSeek 模型。模拟用户确认由测试脚本显式构造，只是测试输入，不代表真实运营人员批准。首次脚本因 UTC 格式比较误判，已保留原报告并按时间语义修正。当前工作区修改的人工作者未单独确认，不据此补写个人贡献；实际验证见 [业务模拟报告](09-business-simulation.md)。
