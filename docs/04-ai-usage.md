# 开发过程与 AI 工具使用

这个项目使用了 AI 辅助开发。我负责明确业务要求和验收标准、检查实现、亲自运行与复验，并根据结果推动修改；Codex 参与代码生成、调试、测试和文档整理。下面分别说明我的工作、复验内容和工具分工。

## 我的工作

我先把题目中的要求落实为几条必须守住的边界：审核不通过不能继续排期；硬性时间不能由模型自行改成已批准的替代时间；保存成功必须有数据库记录；相同请求重复提交不能增加草稿；项目只保存草稿，不接真实发布。

技术方案围绕这些要求展开。我采用原生 Tool Calling、Python CLI 和 SQLite，保留模型选择下一步动作的能力，同时用确定性审核、Policy Guard 和数据库约束控制业务结果。原生工具调用已经足够完成任务，因此没有再引入多 Agent、前端或额外的 Agent 框架。

我还明确了六项基本验收，并要求增加更换占用时段后的重复提交、显式确认、批量素材和保存异常等检查。模型服务和交付仓库由我确定。发现实现与预期不一致时，我要求先复现问题、保留失败记录，再检查修复后的行为。

## 问题复核与改进

我重点检查了“看起来成功，但业务状态可能不正确”的情况。例如，重复提交虽然没有新增数据库行，已有的建议时间却可能已经被占用；保存过草稿，也不代表后来变化的审核结果仍然有效。这些问题需要同时检查工具返回、Trace 和数据库，不能只看模型最后的一段说明。

在复核中，我把已有草稿的时段复查、确认状态、宣传声明字段类型、待确认事项输出、同批素材避让，以及旧审核状态覆盖当前风险等问题纳入验收。具体定位、代码修改和回归测试使用了 Codex 辅助，我负责核对修复是否满足业务要求。相关过程和结果保留在 [审核修复说明](07-review-fixes.md) 与 [状态一致性修复](08-state-consistency-fixes.md) 中。

## 我亲自做的验证

我执行了正常和冲突场景的 CLI，检查了原发布时间、建议时间、确认状态和保存结果；随后重复提交相同请求，核对 draft_id 与数据库记录数量。我也检查了保存失败和需要人工处理的场景，确认它们没有被写成正常排期成功。

我阅读了冲突 Trace，重点核对模型是否先观察到占用，再查询其他时间，以及替代时间是否仍为待确认。对工具拒绝的动作，我检查了拒绝原因和模型后续处理，没有把最终自然语言当作保存成功或用户批准的依据。

复验使用的项目入口如下，完整参数说明见 README：

```powershell
python -m src.main --mode live --input examples/normal.input.json --db runs/personal-normal.db
python -m src.main --mode live --input examples/conflict.input.json --db runs/personal-conflict.db
python -m src.main --mode live --input examples/conflict.input.json --db runs/personal-conflict.db
python -m pytest -q
```

这些是可复现的验证入口。仓库内的自动运行批次由开发会话中的工具产生，不能当作我的个人操作日志。个人复验与自动化验收分开说明；项目归档的输入、输出和测试数字见 [评估报告](03-evaluation.md) 与 [业务模拟报告](09-business-simulation.md)。

## 我复核的关键实现

**模型决策与业务规则的分工。** 模型根据工具观察选择读取、补查、查询或保存；审核结论、确认权限和数据库写入由程序校验。Mock 可以检查工程链路，但不能证明真实模型会自主选择工具，因此真实模型 Trace 单独保存。

**硬性时间与用户确认。** Guard 使用原始请求判断权限。硬性时间的替代建议必须是 PENDING；只有原始输入中存在匹配素材和目标时间的明确确认，才能使用 USER_CONFIRMED。模型修改自己的说明或工具参数，不能代替用户确认。

**幂等与事务。** 请求先规范化并生成指纹，数据库用 `(request_fingerprint, material_id)` 唯一约束防止重复。保存使用 BEGIN IMMEDIATE，把时段复查、Guard 校验和写入放在同一事务内。这样即使换一个进程重新提交，也不依赖模型记忆。仍有效的草稿返回原 ID；失效的待确认建议可以保留 ID 重排并记录旧版本；已批准草稿失效时需要用户处理。

**状态一致性。** 历史保存事实与当前审核结论是两件事。素材缺失、证据读取失败或审核变为阻断后，不能继续输出旧的可用建议。READY 草稿对其他请求占位；待确认建议只在同一请求内互相避让，不能被当成正式排期。

## AI 工具的具体用途

Codex 用于生成和修改 Python 代码、补充测试、辅助定位异常、执行开发命令，以及整理文档和交付材料。开发会话中的依赖安装、pytest、CLI、真实模型调用和 Git 操作均由工具实际执行；这些记录按实际结果归档，失败批次也保留，没有改写为成功。

DeepSeek `deepseek-flash` 是项目运行时使用的模型，负责通过原生 Tool Calling 选择动作。公司公开资料和提供方官方文档用于核对业务背景与接口协议，没有使用公司内部数据。素材、排期和模拟用户确认均为合成测试输入，不代表真实运营批准。

我使用 AI 提高实现和排查效率，同时保留对需求、验收和最终交付的责任。代码是否符合题意、确认边界是否正确，以及每个结果是否有证据，仍然需要我自己检查和解释。
